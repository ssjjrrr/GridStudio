# 发布前性能优化审计

**简体中文** | [English](performance-audit.en.md)

首次正式发布前，以内部优化前快照为基线，对照优化后的开发构建，审查自由画布图层增删、选择与检查器、悬停控件、裁剪绘制、循环/同步时钟及便携版启动验证。优化目标是减少重复界面与控制工作，保留原有视频显示和独立控制能力。

三轮耗时、环境、计数与受测源文件摘要保存在 [performance.json](../benchmarks/performance.json)。以下沿用发布前的内部基线实测记录，不是 1.0.0 或 1.1.0 发布时重新进行的测量；不能据此推断 Linux/macOS 性能。

## 已落地的变化

| 范围 | 发现的开销 | 已落地行为 | 验证 |
| --- | --- | --- | --- |
| 图层新增、复制、删除 | 重建画布时，未变化的窗格也被隐藏和重新设置父窗口 | 对比现有图层，只接入新窗格或移出已删除窗格；保留其余窗格、播放器、位置和悬停状态 | 原有窗格无 Hide/Show/ParentChange，像素和生命周期回归 |
| 播放时钟 | 普通独立播放、原生整段循环和全部暂停仍唤醒控制时钟 | 此时停止控制器定时器；播放中的 A/B 循环与同步组仍每 20 ms 检查 | 定时器活动、唤醒次数、独立播放查询预算、真实循环同步测试 |
| 同步查询 | 一轮内反复读取相同时长 | 单轮缓存时长，下一轮重新读取，避免媒体加载变化后使用旧值 | 不同时长的百分比同步、查询计数和真实媒体测试 |
| 同步组设置 | 循环、速率等连续修改重复应用状态 | 合并同一操作内的状态应用，每个视频应用一次 | 应用次数、暂停/定位/速度/循环语义与加载状态回归 |
| 隐藏的悬停控件 | 不可见时仍格式化时间并请求绘制 | 隐藏时记录数据，再次出现时刷新到当前状态 | 隐藏更新不触发格式化/重绘，出现后时间与按钮状态正确 |
| 裁剪选择 | 局部选择框变化触发整块视频视图更新 | 使用最小视口更新，限制选择框变化的绘制范围 | 裁剪像素、选择框更新区域、旋转/镜像与取消裁剪回归 |
| 选择与检查器 | 重复选择遍历所有画面并重新写入全部字段 | 仅处理原/新选择，检查器仅更新变化字段 | 重复选择无多余属性访问，音量变化只写对应字段，工作区同 ID 替换仍更新正确 |
| 打包验证 | 仅生成截图不能确认视频已解码 | 启动检查同时输出 PNG/JSON，检查全部已打开视频的帧有效性与播放器错误，失败退出非零 | 源码真实媒体测试、便携版进程退出码与解码诊断 |

选框边缘失效区域、重复坐标跳过与控件布局缓存也已落地。

## 测量结果与范围

### 图层管理：有界的界面基准

使用 Windows 原生 Qt 平台、1280×720 逻辑像素窗口，预先显示 16 个 640×360 合成帧图层；执行 20 次复制和删除，每次处理正常的 Qt 事件与绘制队列。基线与优化后构建顺序运行，比较各自三轮结果的中位数。

| 指标 | 优化前内部基线 | 发布前优化后构建 |
| --- | ---: | ---: |
| 20 次复制后删除的总耗时 | 5132 ms | 498 ms |
| 已有图层的 ParentChange 事件 | 1280 | 0 |

该场景总耗时减少 90.3%。输入是合成帧，不包括视频文件打开和实际解码成本；这不是单次鼠标事件延迟、显示器呈现延迟、解码 FPS、最大并发数或普遍适用的加速比。

复现当前版本：

```powershell
.\.venv\Scripts\python.exe benchmarks\workspace_bench.py --platform windows --panes 16 --cycles 20 --output artifacts\workspace-current.json
```

重跑内部对照时使用同一个基准脚本，以 `--project <内部基线源码目录>` 选择基线快照。每个构建至少顺序运行三轮；相同机器、缩放、窗口和输入条件下比较中位数。不要同时运行解码测试或其他基准。内部基线快照需另行提供，当前公开源码用于重跑当前侧结果。

同轮四层 3840×2160 合成帧、120 次移动与 120 次缩放的中位耗时分别为 165.5 → 155.4 ms、235.7 → 224.7 ms。最终几何一致，但这两个小差值与轮次波动相当，不作为显著加速承诺。

### 同步控制：确定性的工作量计数

8 个不同时长的百分比同步视频、50 轮检查中，受测播放器查询由 4000 次降至 1550 次（减少 61.3%）。加入同步组时，每个视频的状态应用由 3 次合并为 1 次。

此项使用计数播放器隔离控制逻辑；不是 CPU 占用、能耗、耗时或真实解码负载的测量。测试同时覆盖时长变化、时间偏移、A/B 边界、漂移校正与加载未完成状态，避免用永久缓存换取较少查询。

可通过 `benchmarks/playback_query_bench.py --baseline <内部基线源码目录> --output <结果.json>` 重跑；该脚本使用当前测试中的计数播放器，分别加载基线与当前控制器，50 轮检查为手动调用，不在计数区间处理 Qt 事件循环。实际定时器是否活动单独记录。

## 保持不变的行为

- 视频分辨率、画面质量和渲染采样质量不因本轮优化降低；拖动画面时继续正常播放。
- 同视频副本仍保留独立播放器与解码路径，可分别定位、变速、播放或加入同步组。本轮没有引入共享解码器。
- Qt 已有遮挡区域绘制优化。本轮没有对整块画布强行声明不透明，也没有另加未经验证的 GPU/OpenGL 渲染路径；原比例留白透明和鼠标穿透继续可用。
- A/B 循环与同步组播放时维持原有 20 ms 检查间隔及漂移校正语义，未通过降低检查频率换取空闲指标。
- 网格、聚焦、复制变换、工作区格式、悬停操作和音频的独立设置继续保留。

## 验证材料

相关工作量与正确性回归主要位于 `tests/test_render_perf.py`、`test_playback_perf.py`、`test_app_perf.py`，并与现有画布像素、真实解码、循环同步和窗格生命周期测试共同执行。测试方法、隔离的真实悬停检查、死锁子进程和 CI 构建说明见 [development.md](development.md)。

测试调用次数是可重复的结构约束；基准耗时会随机器和系统状态变化。另一轮内部移动/缩放优化记录单独保留在 [benchmarks/README.txt](../benchmarks/README.txt)，其数字不能与这里的图层增删结果直接合并。
